# Практика ЕГЭ · Telegram · версия 2

Личный тренажёр по информатике: от первого логического знака до самостоятельного решения. Без ИИ, API-ключей моделей и платной генерации. Проект использует актуальный формат Telegram Rich Messages с LaTeX, нативные кнопки и опциональные custom emoji.

## Что уже реализовано

Сохранены выбор темы, смешанная тренировка, новые варианты, проверка, просмотр решения, дневная цель 10 задач, точность, серия, сохранение прогресса и подтверждаемый сброс дня. В экзаменационной практике ответ вводится вручную: число, двоичный код или порядок переменных.

Дополнительно:

- 16 экзаменационных семейств и отдельно 5 разминок по основам логики.
- Фано: кратчайший код, минимальная сумма длин двух неизвестных кодов, минимальная длина слова с учётом частот букв.
- Таблица истинности с пропусками: все 24 перестановки проверяются, ответ всегда однозначен.
- Двоичные алгоритмы, подсчёт программ с обязательной и запрещённой точками.
- Прямые и обратные задачи на звук, изображения и память; слова с ограничениями и поиск номера слова.
- Расчётная формула скрыта до второй подсказки, пошагового режима или разбора; выражение из условия логической задачи видно сразу.
- Короткие уроки с нуля, примеры и запоминание просмотренной карточки урока.
- Логика по маршруту НЕ → И → ИЛИ → следование → выражения.
- Пошаговый режим для каждой темы: отдельный ответ на каждое действие, а не просто раскрытие готового решения.
- Две последовательные подсказки и возможность перейти от самостоятельного решения к совместному.
- Раздельный учёт самостоятельных решений и решений с помощью.
- Список тем для повторения после ошибки или просмотра ответа; два самостоятельных успеха по теме убирают её из списка.
- Статистика по подтипам и за всё время. Дневная цель 5, 10 или 20 задач.
- Незавершённая задача и её текущий шаг переживают перезапуск.
- Локальная база SQLite, закрытый доступ по умолчанию, возможность открыть бота другим пользователям.
- Опциональное напоминание по времени Барнаула; по умолчанию выключено.
- Native LaTeX и читаемый обычный режим на выбор. Премиум-значки назначаются из чата владельцем.
- systemd, опциональный Docker Compose, безопасное резервное копирование и автономные тесты.

Это не ИИ-чат: бот не понимает свободные вопросы вида «почему вообще существует импликация?». Для объяснений есть уроки, подсказки и пошаговый режим. Все объяснения подготовлены заранее и подставляют данные текущей задачи.

## Первый запуск: Linux / Ubuntu, Python 3.11+

Не нужны сайт, домен, входящие порты и сертификат. Нужен сервер с исходящим HTTPS-доступом к `api.telegram.org`. Никакие существующие VPN и другие боты проект не изменяет.

1. Создай **нового** бота через https://t.me/BotFather командой `/newbot` со своего Premium-аккаунта. Не используй токен работающего бота расписания или уведомлений.
2. Распакуй архив. Например, проект может лежать в `/root/ege_bot` для ручного теста.
3. В папке проекта:

```bash
python3 --version
cp .env.example .env
chmod 600 .env
nano .env
```

Впиши `BOT_TOKEN`. Токен никому не отправляй и не публикуй. Пока `OWNER_ID=0`, обычный запуск специально запрещён.

4. Узнай свой ID через самого бота:

```bash
python3 bot.py --whoami
```

Открой своего бота в Telegram и отправь `/id`. Он ответит твоим ID; то же число появится в консоли. Сверь их, останови режим через Ctrl+C и укажи число в `OWNER_ID` файла `.env`. Этот режим **не назначает владельцем первого посетителя**. Не запускай его одновременно с основным процессом бота.

5. Запусти:

```bash
python3 -m unittest discover -s tests -v
python3 bot.py
```

Открой чат и отправь `/start`. Дальше управление кнопками. Ответ в экзаменационной задаче отправляй сообщением. Варианты 0/1 остались только в самостоятельных разминках по логическим операциям.

Проект использует стандартную библиотеку Python: `pip install` и виртуальное окружение не требуются. На минимальном Linux может понадобиться системный пакет `tzdata`. Рекомендуется Python 3.12 из Ubuntu 24.04. Windows не поддерживается этим вариантом службы из-за Linux-блокировки процесса (`fcntl`); можно использовать Docker на Linux/WSL.

## Интерфейс и методика

Главное меню: «Продолжить», «Учиться с нуля», «Задания ЕГЭ», «Повторить ошибки», «Прогресс», «Настройки», «О боте».

Карточка — заголовок, условие, текущий шаг или открытая подсказка, кнопки. Формулы решения не показываются заранее. Логическое выражение и таблица являются условием и видны сразу. Меню редактируется на месте. После ответа новая рабочая карточка появляется ниже сообщения ученика; предыдущие рабочие кнопки снимаются, когда это возможно. Старые карточки не могут изменить новую задачу: проверяются ID сообщения и ревизия кнопок.

Внешний вид — нативный Telegram: типографика и светлая/тёмная тема берутся из клиента. Это не Mini App: произвольные фоны, CSS-анимации и собственную сетку экрана обычный бот не рисует. Основная кнопка выделена синим, опасное удаление — красным; успешность объясняется текстом, а не только цветом. Эмодзи используются умеренно, на основных пунктах меню.

Серии считаются только по самостоятельным верным ответам за текущий день. Подсказка, теория текущей темы, пошаговый режим и показ решения означают помощь. Неверный самостоятельный ответ завершает попытку и показывает разбор. В пошаговом режиме ошибку можно исправить; задача всё равно считается решённой с помощью. Неправильный формат ответа не портит статистику.

Цель дня и точность считают все верные завершения, включая решения с помощью; самостоятельные отдельно видны рядом. Отсчёт дня — по `TIMEZONE`, по умолчанию `Asia/Barnaul`, не по UTC.

Сброс дня удаляет только сегодняшние попытки и активную задачу; уроки и ошибки остаются. Удаление всего прогресса дополнительно очищает уроки, ошибки и выключает напоминания. Оба действия требуют подтверждения. Это удаление учебной истории, не полное удаление Telegram ID и настроек интерфейса.

## LaTeX, цветные кнопки и премиум-эмодзи

Формулы отправляются как `InputRichBlockMathematicalExpression` внутри `sendRichMessage`, не как псевдо-LaTeX обычного `sendMessage`. Меняется карточка через `editMessageText` с `rich_message`. Основные кнопки используют `InlineKeyboardButton.style`.

По умолчанию выбран Rich-режим. При явном ответе сервера о неподдерживаемом формате предусмотрен переход на обычные HTML-сообщения. Если сервер принимает Rich Messages, но старый клиент показывает их плохо, бот этого определить не может: переключи **Настройки → Обычный текст**. Сложные формулы в этом режиме заменяются читаемыми текстовыми выражениями, не изображениями.

Для custom emoji нужен Premium **у фактического владельца бота в BotFather**. Указание `OWNER_ID` не меняет владельца в Telegram. Мы используем эмодзи в напрямую отправляемых ботом личных сообщениях/кнопках; бот не работает от имени твоего личного аккаунта и не получает доступа к его переписке.

Выбери четыре спокойных значка из одного набора. Для каждой роли:

1. Пришли боту одно премиум-эмодзи отдельным обычным сообщением (не стикером).
2. Ответь на это сообщение одной из команд:

```text
/emoji learn
/emoji practice
/emoji review
/emoji stats
```

Бот возьмёт реальный `custom_emoji_id` из ответа. Подставных идентификаторов нет. `/emoji_clear` возвращает меню без custom emoji. Настройка доступна только `OWNER_ID`. Если Telegram явно отклоняет эмодзи, отправка повторяется с обычными кнопками; расчёты не зависят от декора.

Аватар, имя и описание установи в BotFather. Подходящее имя: **Практика ЕГЭ • Информатика**. Описание: «Решай задания ЕГЭ, изучай основы и разбирай ошибки. Подсказки, пошаговые решения и прогресс — в Telegram. Без ИИ». Готового собственного набора премиум-эмодзи в архиве нет: используются выбранные тобой существующие эмодзи.

## Постоянная работа через systemd

Ручной процесс сначала останови Ctrl+C. Команды ниже рассчитаны на новый каталог `/opt/ege-bot`. Если каталог или пользователь `ege-bot` уже существуют, сначала проверь их, не перезаписывай чужой проект.

Из папки распакованного проекта, от root:

```bash
useradd --system --home-dir /opt/ege-bot --shell /usr/sbin/nologin ege-bot
install -d -o ege-bot -g ege-bot /opt/ege-bot
cp -a . /opt/ege-bot/
install -d -o ege-bot -g ege-bot /opt/ege-bot/data
chown -R ege-bot:ege-bot /opt/ege-bot
chmod 600 /opt/ege-bot/.env
cp deploy/ege-bot.service /etc/systemd/system/ege-bot.service
systemctl daemon-reload
systemctl enable --now ege-bot.service
systemctl status ege-bot.service --no-pager
```

Служба не запускается от root и пишет только в `data`. Если меняешь `DATABASE_PATH`, скорректируй `ReadWritePaths` в службе. Не делай папку базы общедоступной.

Логи:

```bash
journalctl -u ege-bot.service -n 80 --no-pager
```

Бот не записывает токены, тексты учеников или ответы API в журнал. Ошибки показывают тип/код; текущая задача обычно восстанавливается командой `/continue`. Для подробной отладки воспроизведи проблему локально с тестовым ботом, не публикуй реальные токены.

## Docker — альтернативный способ

Не запускай одновременно Docker и systemd с одним токеном. Останови другой экземпляр сначала.

```bash
docker compose up -d --build
docker compose logs --tail=80
```

Конфигурация читается из `.env`, данные — в именованном томе `bot-data`. Не используй `docker compose down -v`, если хочешь сохранить прогресс. Docker-образ необходимо скачать при первой сборке. Версия Python в Docker — 3.12.

## Напоминания

В боте они выключены по умолчанию, поскольку напоминание ChatGPT уже настроено отдельно. Включить можно в настройках или командой:

```text
/remind 20:00
/remind off
```

Часовой пояс задаётся один для установки: `Asia/Barnaul` (UTC+7). В личном использовании это твой часовой пояс. Для публичного многорегионального сервиса потребовались бы индивидуальные часовые пояса.

Проверка выполняется примерно раз в 20 секунд, при отсутствии ошибок сети. После перезапуска допускается доставка в течение часа после заданного времени; более старые напоминания пропускаются. Бот намеренно не пересылает напоминание при неоднозначном сетевом сбое: важнее избежать дубля. Это не механизм гарантированной доставки. Изменение напоминаний здесь **не меняет** задачу ChatGPT.

## Резервная копия

Для обычной установки в папке проекта:

```bash
python3 backup.py --database data/ege.sqlite3 --output backups
```

Используется SQLite Backup API, поэтому копия согласована даже при работающем боте. Храни копию вне сервера в защищённом месте. Не копируй один файл работающей WAL-базы обычной командой `cp`: часть данных может быть в файле WAL.

В Docker:

```bash
docker compose exec ege-bot python -c "import sqlite3; s=sqlite3.connect('/app/data/ege.sqlite3'); d=sqlite3.connect('/app/data/backup.sqlite3'); s.backup(d); d.close(); s.close()"
docker compose cp ege-bot:/app/data/backup.sqlite3 ./backup.sqlite3
```

Восстановление: останови бота, сохрани старый каталог `data` целиком отдельно, создай чистый каталог `data`, помести туда резервную копию под именем `ege.sqlite3` и верни права пользователя службы. Не подмешивай к восстановленной базе старые `-wal` и `-shm`.

## Ограничения, устойчивость и безопасность

- Один процесс и long polling: подходит для личного тренажёра и небольшого числа пользователей, не обещает масштаба массовой платформы.
- `PUBLIC_ACCESS=false` по умолчанию. Доступ не может захватить первый пользователь.
- Настройки, данные, статистика и задачи разделены по Telegram ID. Группы игнорируются.
- Токен используется только для Bot API; сессия личного Telegram-аккаунта не нужна.
- При обнаружении webhook бот останавливается, не удаляет его автоматически. Для этого проекта лучше отдельный бот.
- Повторное завершение одного задания не увеличивает счётчик. Старые кнопки отвергаются.
- Сетевой сбой после отправки может иметь неоднозначный результат: бот не повторяет `send*` вслепую. Возможны пропущенные визуальные ответы; `/continue` восстанавливает сохранённую задачу.
- 429 обрабатывается с учётом `retry_after`; при 401/409 служба останавливается с кодом 2. Проверь токен и отсутствие второго экземпляра, затем запусти вручную.
- Этот архив не был подключён к реальному боту: у разработчика нет твоего токена. Локально проверены вычисления, сценарии и формирование JSON-запросов. Отображение на твоём клиенте Telegram нужно проверить после запуска.

## Контрольная проверка после запуска

1. `/start`: меню отображается, кнопки работают.
2. Учиться с нуля → Логика → НЕ: прочитай пример, реши по шагам.
3. Задания ЕГЭ → Изображения и звук: видишь условие без формулы решения; введи число.
4. Возьми подсказку: результат учитывается «с помощью».
5. Ответь неправильно: тема появляется в ошибках; два самостоятельных успеха убирают её.
6. Перезапусти процесс на середине задачи и отправь `/continue`.
7. Нажми кнопку в старой карточке: она не должна изменять текущую задачу.
8. Настрой один премиум-значок; при проблемах проверь фактическое владение ботом и Premium.
9. Открой настройки: напоминания по умолчанию выключены.
10. Задания ЕГЭ → Кодирование: код вводится вручную; начальные нули не теряются.
11. Задания ЕГЭ → Логика: выражение и таблица видны; ответ из четырёх латинских букв принимается.

## Структура проекта

`bot.py` — запуск, polling, блокировка процесса; `ege/tasks.py` — модель задания, основы логики и разбор ответа; `ege/exam.py` — экзаменационные генераторы; `ege/lessons.py` — учебный материал; `ege/db.py` — SQLite; `ege/app.py` — учебные сценарии; `ege/ui.py` — карточки, LaTeX и fallback; `ege/telegram.py` — HTTPS Bot API с приоритетом IPv4; `tests/` — автономные проверки.

Проверки: 1600 экзаменационных вариантов по независимым эталонам и перебору, 750 разминок,
однозначность логики, минимальность Фано, округления и ограничения памяти, типы ответов,
оба режима отображения, пошаговые сценарии, защита от повторного зачёта, старая база и IPv4/IPv6.
